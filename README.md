# AI Wardrobe｜数字衣柜

面向换季、搬家及长期收纳场景的个人物品管理 Web Demo。  
项目从真实收纳痛点出发，通过「图片录入—待整理箱—分类浏览 / 搜索—位置维护」建立物品管理闭环，解决两个核心问题：

- **找得到**：记得拥有某件物品，但忘记具体存放位置；
- **想得起**：通过分类浏览重新发现已经遗忘的物品。

🔗 **Live Demo:** https://ai-wardrobe-4c1.pages.dev

---

## Product Background

项目来源于个人在本科、硕士阶段长期异地学习和换季整理中的真实体验：非当季及低频物品长期存放后，容易出现“记得有，但忘记放在哪里”，甚至“忘记自己拥有这件物品”的情况。

同时，在一次性整理大量物品时，如果要求逐件手动录入名称、类别和位置，又会产生较高的操作成本。

因此，我将需求拆解为三个核心场景：

1. **集中整理**：换季、搬家等情况下快速建立物品记录；
2. **后续查找**：通过名称搜索快速确认物品及最后记录位置；
3. **物品再发现**：通过分类浏览重新看到已经被遗忘的物品。

---

## Core Product Flow

**添加物品 → 待整理箱 → 分类 → 分类浏览 / 搜索 → 查看详情 → 确认或更新储存位置**

核心产品规则包括：

- 图片、物品名称为必填项；
- 储存位置选填，但鼓励记录；
- 新录入物品统一进入「待整理箱」，录入与分类分离；
- 未分类物品仍然可以被搜索；
- 搜索解决明确查找需求，分类浏览承担物品再发现；
- 使用「最后记录位置」而非「当前位置」，避免对现实位置准确性作过度承诺；
- PC 与移动端提供等价的核心操作路径。

## AI Design

AI 在本项目中被定位为**降低录入成本的辅助能力**，而不是产品成立的前提。

规划中的 AI 流程为：

**上传图片 → AI 提供名称 / 分类建议 → 用户确认或修改 → 保存**

同时保留人工填写作为识别失败时的兜底路径，避免 AI 失败阻断核心流程。

> **Current Scope:** 当前 Demo 尚未接入真实 AI 模型，因此不宣称模型识别准确率或真实 AI 效果。现阶段重点验证产品流程、交互逻辑与产品边界。

## Key Design Decisions

### 1. 录入与分类分离
用户可以先快速完成物品录入，再通过「待整理箱」集中完成分类，降低大规模整理时的操作负担。

### 2. Search + Browse 双路径
- **Search**：服务于“我知道自己要找什么”
- **Browse**：服务于“我想看看自己拥有什么”

### 3. 轻拟物 + 标准化效率界面
首页以模块化衣柜和箱子建立空间隐喻；搜索、编辑、详情等高效率任务采用标准化 UI，避免视觉趣味增加操作成本。

### 4. AI 不阻断核心流程
即使 AI 不可用，用户仍可以通过人工录入、分类、搜索和位置维护完成完整任务。
