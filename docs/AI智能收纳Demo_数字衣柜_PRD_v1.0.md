## 执行摘要

本产品面向拥有较多衣物、鞋包及低频个人物品，并在换季、搬家或长期收纳后容易忘记物品位置的个人用户。V1 通过图片录入、待整理箱、分类浏览、名称搜索和位置维护，建立从整理记录到后续查找的完整闭环。

产品同时支持两种取回方式。搜索解决用户知道要找什么时的精确检索，分类浏览解决用户忘记自己拥有什么时的物品再发现。二者共同决定了名称、图片、分类和最后记录位置的字段设计。

AI 的定位是降低从图片到结构化信息的录入成本。它只提供名称和分类建议，用户保留最终决定权；识别失败时可直接手动填写。当前 Demo 尚未接入真实模型，因此 V1 开发必须提供可切换的模拟识别状态，并保证所有核心流程在没有 AI 的情况下仍可完成。

V1 采用单用户模式，不实现注册登录、跨设备同步、批量上传、穿搭推荐或电商能力。完成标准不是功能数量，而是核心链路可连续运行、状态变更一致、异常可恢复，并能在 PC 和移动端完成同一任务。

## 1 产品概述与需求来源

### 1.1 产品概述

AI 智能收纳 Demo 数字衣柜是一款个人物品数字化记录与检索工具。用户为单件物品上传图片、确认名称并可选记录储存位置，保存后物品进入待整理箱；用户随后可将物品分配到自定义分类，并通过名称搜索或分类图片网格再次找到它。

产品视觉以轻拟物的模块化柜门建立衣柜心智模型，具体录入、搜索、编辑和管理任务使用标准化卡片与表单。轻拟物只服务分类理解与浏览趣味，不改变用户完成任务的标准路径。

### 1.2 需求来源

需求来源于个人长期的真实收纳经验。本科和硕士阶段长期异地学习，换季、搬家或返家整理时，会将非当季衣物、低频用品和阶段性非必需品带回家中，分散存放在房间内不同柜体和收纳箱。由于物品使用频率低、存放周期长，下一次需要使用时往往只能记得曾经收起，却无法准确回忆具体位置。

大规模整理时逐件输入名称、分类和位置又需要较多时间。由此形成一条明确的需求链路：集中整理需要快速建库，后续使用需要低成本检索，日常变化需要轻量维护。AI 图像识别被设想为降低初始录入成本的辅助能力，而不是产品成立的前提。

### 1.3 需求证据与限制

- 现有需求证据来自个人真实使用情境和对完整流程的产品拆解，尚未进行正式用户访谈或量化可用性测试。
- 当前不能宣称录入效率提升、AI 识别准确率、用户留存或搜索成功率等量化结果。
- 后续若进入验证阶段，可招募 5 至 8 名目标用户开展任务制可用性测试，再补充真实发现和指标。

## 2 问题定义

### 2.1 Problem Statement

在换季、搬家等集中整理场景中，低频物品会被分散存放于多个储物空间。存放周期较长时，用户容易忘记具体位置，甚至忘记自己拥有某件物品；但逐件记录图片、名称、类别和位置又有较高操作成本。产品需要在不强制填写全部字段、不依赖 AI 必须成功的前提下，降低从整理记录到再次寻找的整体成本。

### 2.2 需要解决的用户问题

| **阶段** | **用户问题** | **产品回应** |
| --- | --- | --- |
| 集中整理 | 物品多  逐件输入耗时 | 单件快速录入  支持连续添加  AI 提供建议但不阻塞 |
| 归类整理 | 录入与分类连续进行会加重负担 | 所有新物品先进入正常状态的待整理箱  稍后再分类 |
| 后续查找 | 知道物品名称但忘记位置 | 名称搜索  结果直接展示最后记录位置与状态 |
| 物品再发现 | 忘记自己拥有某件物品 | 分类图片网格帮助浏览已有物品 |
| 日常维护 | 现实位置变化但数字记录可能过期 | 使用最后记录位置措辞  提供确认  更新与待确认动作 |

### 2.3 核心产品假设

- 将录入与分类拆开，可以降低集中整理时的单件操作负担。
- 图片必填、名称必填、位置选填，可以同时支持视觉识别、检索和低门槛建库。
- 待整理箱作为正常状态而非待办警告，可以让用户在未分类时仍然完整使用搜索与详情能力。
- 搜索与分类浏览需要并存，因为二者分别服务明确查找与模糊再发现。
- AI 提供建议并允许纠错，比自动替用户完成最终分类更符合模型不确定性和个人分类差异。

## 3 目标用户与核心场景

### 3.1 目标用户

V1 的核心用户是拥有较多衣物、鞋包或低频个人物品，并存在集中整理、位置记忆或分类浏览需求的个人用户。用户不需要具备专业资产管理习惯，产品应允许其以日常语言命名物品和位置。

当前 PRD 不构造年龄、职业或收入等未经验证的人口统计画像。后续测试应优先覆盖有换季整理、异地居住、搬家或多储物空间经验的用户。

### 3.2 三类核心场景

| **场景** | **触发与任务** | **成功结果** | **设计重点** |
| --- | --- | --- | --- |
| 集中整理 | 换季  搬家  返家或大规模整理时连续记录多件物品 | 物品以最少必要信息成功进入物品库 | 单件录入  连续添加  图片和名称校验  AI 失败可手填 |
| 后续查找 | 用户记得物品但忘记存放位置 | 通过名称快速确认目标并看到最后记录位置 | 实时名称搜索  相似物品用图片区分  位置状态可信表达 |
| 分类浏览与再发现 | 用户没有明确目标  想查看自己拥有什么 | 浏览图片后重新想起物品并可查看位置 | 模块化柜门  图片网格  连续浏览  详情不打断上下文 |

### 3.3 次级场景

- 日常增量记录  新购或临时收纳一件物品时快速新增。
- 位置维护  用户找到或移动物品后顺手确认或更新位置。
- 分类维护  用户根据个人习惯新增  重命名  排序或删除分类。

## 4 产品目标与设计原则

### 4.1 V1 产品目标

1. 完成从单件录入到后续检索的可运行闭环。

2. 降低集中整理中的重复操作，并允许用户连续录入。

3. 让未分类物品仍可被搜索、查看和编辑。

4. 通过图片网格支持个人物品浏览与再发现。

5. 建立可解释、可纠错、失败可兜底的 AI 交互框架。

### 4.2 设计原则

| **原则** | **产品含义** |
| --- | --- |
| 核心价值先于 AI | 即使模型不可用  手动记录  分类  搜索和位置维护仍需完整可用 |
| 录入与分类分离 | 保存成功只代表建立记录  不要求同时完成分类 |
| AI 推荐  用户决定 | 名称与分类建议均可修改  AI 不自动完成最终归类 |
| 探索任务保留趣味 | 首页柜门与箱子可轻拟物  强化空间隐喻和再发现 |
| 目标任务优先效率 | 搜索  编辑  更新位置和设置使用标准化交互 |
| 状态表达不夸大 | 显示最后记录位置  不承诺系统掌握现实当前位置 |
| 危险操作可预期 | 删除和迁移明确说明影响范围  分类删除不删除物品 |
| 跨设备任务一致 | PC 可提供拖拽效率  移动端必须有点击选择的等价路径 |

### 4.3 建议验证指标

以下指标用于后续测试设计，不代表当前已有数据。

- 录入完成率  用户开始上传后成功保存到箱子的比例。
- 单件录入时长  从选择图片到保存成功的用时。
- 连续录入成功率  用户连续完成两件及以上物品录入的比例。
- 搜索成功率  用户能否在限定时间内找到目标记录并读出位置。
- 分类完成率与撤销率  判断拖拽和分类选择是否易懂。
- AI 建议采纳率与纠正率  模型接入后评估名称和分类建议质量。

## 8 用户流程与物品状态

### 8.1 集中整理与录入流程

1. 用户从衣柜首页进入添加物品。

2. 用户拍摄或选择一张图片  未选择图片时不能保存。

3. 系统进入 AI 识别状态  用户不必等待  可直接填写名称。

4. 若有建议  系统填入建议名称并展示建议分类  用户可修改。

5. 用户可选择常用位置或输入新位置  该字段选填。

6. 用户选择保存到箱子或保存并继续添加。

7. 系统生成记录并设置 category_id 为空  新物品按 created_at 出现在箱子顶部。

8. 用户稍后通过拖拽或点击选择将物品放入分类。

### 8.2 后续查找流程

1. 用户在首页搜索框输入物品名称。

2. 系统实时返回已分类和未分类的匹配记录。

3. 结果直接展示图片  名称  最后记录位置与分类状态。

4. 用户打开详情并按照记录位置寻找实物。

5. 找到且位置正确时确认位置  找到但位置变化时更新位置  未找到时标记位置待确认。

### 8.3 分类浏览与再发现流程

1. 用户从首页打开某个分类柜门。

2. 系统以图片网格展示该分类的全部物品  默认最近添加优先。

3. 用户通过图片识别被遗忘的物品  点击后在当前上下文查看详情。

4. 用户可继续浏览  更新位置或移动分类  详情关闭后保留原列表位置。

### 8.4 分类状态流转

| **当前状态** | **触发动作** | **目标状态** | **系统行为** |
| --- | --- | --- | --- |
| DRAFT | 完成必填校验并保存 | UNCLASSIFIED | 写入记录  category_id 为空  进入箱子 |
| UNCLASSIFIED | 选择或拖入分类 | CLASSIFIED | 写入 category_id  从箱子移除  分类数量加一 |
| CLASSIFIED | 移动到其他分类 | CLASSIFIED | 替换 category_id  两个分类计数同步 |
| CLASSIFIED | 移回待整理箱 | UNCLASSIFIED | 清空 category_id  按原 created_at 回到箱子 |
| CLASSIFIED | 所在分类被删除 | UNCLASSIFIED | 清空 category_id  物品不删除  按原 created_at 排序 |
| 任一已保存状态 | 删除物品并确认 | DELETED | 删除图片与关联记录  V1 不提供回收站 |

### 8.5 位置状态流转

| **当前状态** | **动作** | **目标状态** | **保留信息** |
| --- | --- | --- | --- |
| UNSET | 添加位置 | RECORDED | 位置名称  更新时间 |
| RECORDED | 位置正确 | RECORDED | 位置不变  更新确认时间 |
| RECORDED | 更新位置 | RECORDED | 新位置  新更新时间 |
| RECORDED | 未在该位置找到 | UNCERTAIN | 保留上次记录位置  标记待确认 |
| UNCERTAIN | 更新位置 | RECORDED | 以新位置覆盖有效记录  更新确认信息 |

### 8.6 AI 状态流转

| **状态** | **含义** | **用户可执行动作** |
| --- | --- | --- |
| IDLE | 尚未选择图片 | 选择图片或拍照 |
| PENDING | 正在尝试识别 | 等待  也可直接填写名称 |
| RECOGNIZED | 已返回名称或分类建议 | 确认  修改  保存 |
| FAILED | 未返回有效建议 | 手动填写名称并继续 |
| CORRECTED | 用户修改了 AI 建议 | 按最终值保存  后台可记录差异 |

## 9 页面与交互规则

### 9.1 衣柜首页

- 添加物品是页面内主要操作  可使用右下角浮动按钮或稳定的突出按钮  不放入底部一级导航。
- 底部一级导航仅有衣柜与设置。

### 9.2 添加物品

| **区域** | **规则** |
| --- | --- |
| 图片 | 单件一张主图  图片必填  支持拍照或相册选择  V1 不裁剪  不多图 |

校验顺序为图片  名称。位置未填不阻断保存。AI 识别失败不能成为错误终点，界面应使用暂未识别出物品信息  请补充名称等可行动文案。

### 9.3 待整理箱

- 桌面端从右侧打开约占页面三成宽度的 Drawer  打开后衣柜保持可见且可交互  不使用会锁死背景的深色遮罩。

- 列表按 created_at 倒序  分类删除导致物品回箱时不改 created_at。
- 卡片展示图片  名称  有则显示位置  有则显示 AI 建议分类  不重复显示未分类标签。
- 桌面端允许把卡片拖到柜门。拖拽时可放置柜门进入高亮  AI 推荐柜门只做轻提示。
- 松手在空白区域时卡片回原位  不弹错误提示。
- 点击移动到分类打开选择列表  推荐项置顶但不强制。成功后同步数量并提供短时撤销。
- 点击卡片打开统一物品详情。箱子物品与已分类物品一样可以被搜索。

### 9.5 搜索

- 搜索范围为全部已保存物品  包括已分类和箱子中的未分类物品。

- 结果使用图片加信息的列表卡片  信息顺序为图片与名称  最后记录位置  分类状态。
- 位置为空时明确显示尚未记录位置  状态为 UNCERTAIN 时显示位置待确认与上次记录。

## 11 AI 识别与反馈机制

### 11.1 当前实现状态

当前 Demo 尚未接入真实 AI 模型。产品界面可以模拟识别加载、识别成功和未识别状态，以验证流程与文案；任何演示数据都不得描述为真实模型输出或准确率结果。核心功能必须在 AI 关闭或失败时仍可完成。

### 11.2 建议的模型输入与输出

| **环节** | **定义** |
| --- | --- |
| 输入 | 用户上传的一张物品图片 |
| 建议输出 | suggested_name  suggested_category_id 或 suggested_category_name |
| 不应输出 | 储存位置  因图片无法知道用户把物品放在哪里 |
| 最终写入 | 用户确认后的 final_name  最终分类仍由后续归类动作决定 |

### 11.3 成功 失败与超时

- PENDING 时显示正在识别物品信息  但不禁用名称输入。
- RECOGNIZED 时将建议名称填入可编辑输入框  建议分类作为辅助信息保留。
- FAILED 或超时时显示暂未识别出物品信息  请补充名称  不使用强烈报错语气。
- 用户已手动输入名称后  迟到的模型结果不得覆盖用户文本。
- 模型失败不影响图片上传成功状态  用户可完成保存。

### 11.4 用户纠错

用户修改 AI 名称或最终选择不同分类时，以用户值为最终业务值。界面不需要每次弹出是否反馈给 AI 的确认，因为这会打断连续录入。后台可将预测与最终结果分字段记录，用于未来评估，但当前 Demo 不执行模型训练。

### 11.5 潜在反馈数据机制

| **数据** | **用途** | **V1 状态** |
| --- | --- | --- |
| 图片与预测名称 | 分析模型输出 | 仅预留字段  不产生真实调用 |
| 最终名称 | 计算名称修改率  建立个人词典候选 | 可记录用户输入 |
| 预测分类与最终分类 | 计算分类建议采纳率 | 可预留差异字段 |
| 失败类型与耗时 | 定位超时  无结果或解析错误 | 真实模型接入后记录 |
| 用户授权状态 | 决定纠错数据是否可用于全局模型优化 | V1 不收集  不展示授权入口 |

### 11.6 个性化与全局训练的区分

个人化记忆可以通过用户历史标签、词典或相似物品匹配实现，例如优先使用用户习惯的防晒衣命名。全局模型优化则需要积累、清洗、标注和评测数据，并必须在取得用户明确授权和满足隐私要求后进行。用户一次纠错不等于模型即时学习。

## 12 分类与储存位置管理

### 12.1 分类管理规则

| **操作** | **规则** |
| --- | --- |
| 默认分类 | 首次初始化为上装  下装  鞋子  包包  均可修改或删除 |
| 新增 | 只填写名称  同一用户下不允许完全同名  创建后出现在首页 |
| 重命名 | 分类标识不变  分类下物品不受影响  所有入口同步新名称 |
| 排序 | 拖拽调整 sort_order  首页柜门立即同步 |
| 删除空分类 | 二次确认后删除 |
| 删除非空分类 | 确认文案显示物品数量  删除分类但不删除物品  物品 category_id 清空并回箱 |
| 回箱排序 | 保留物品原 created_at  不把因分类删除而回箱的旧物品推到顶部 |

### 12.2 常用储存位置规则

V1 将一个储存位置视为一个完整名称，例如主卧衣柜 顶柜或床下 1 号收纳箱，不建立房间  家具  层板的层级树。用户可以自行决定描述粒度。

| **操作** | **规则** |
| --- | --- |
| 新增 | 填写位置名称后加入快捷选择列表  可立即用于新增和更新位置 |
| 重命名 | 视为同一个真实位置名称变化  同步更新所有仍关联该位置的物品显示 |
| 排序 | 调整 sort_order  新增物品和更新位置选择器按此顺序展示 |
| 从常用位置中移除 | 只将 is_active 设为 false 或移出快捷列表  不清空已有物品的历史位置 |
| 已有关联的移除提示 | 明确说明不再出现在常用列表  已有物品位置记录不受影响 |

### 12.3 分类与位置的语义差异

分类是物品当前所处的组织结构，因此分类删除后该关系不能继续成立，物品需要回到箱子。常用位置是快捷输入对象，物品中的最后记录位置是历史事实，因此位置从快捷列表移除后，历史记录仍应保留。

## 13 搜索逻辑

### 13.1 查询范围与字段

- 数据范围为全部已保存且未删除的物品  不按分类状态过滤。
- 搜索字段仅为最终物品名称 final_name 或 name。
- 匹配方式为名称包含关键词  中文按连续字符串匹配  V1 不做同义词和语义扩展。
- 输入为空时不展示搜索历史  可显示简洁的输入提示。

### 13.2 排序

1. 名称完全匹配优先。

2. 名称包含关键词的记录随后展示。

3. 同等匹配度下按 updated_at 倒序  若尚未实现精细排序  可统一按 updated_at 倒序。

### 13.3 结果结构

| **字段** | **展示规则** |
| --- | --- |
| 图片 | 必显  用于区分同名或相似物品 |
| 名称 | 必显  关键词可做轻量高亮 |
| 位置 | RECORDED 显示最后记录位置  UNSET 显示尚未记录位置  UNCERTAIN 显示位置待确认 |
| 分类 | 显示具体分类  未分类显示待整理箱 |
| 详情 | PC 右侧面板  移动端 Bottom Sheet |

### 13.4 不支持的搜索能力

- 按分类  位置  品牌  颜色  材质或标签检索。
- 自然语言问答  语义召回  同义词扩展或相似物品推荐。
- 搜索历史  热门搜索  个性化排序或复杂筛选。

## 15 异常与边界情况

| **情况** | **系统行为与文案原则** |
| --- | --- |
| 未上传图片 | 保存按钮不可提交或提交时就地提示请上传物品图片  不创建记录 |
| 名称为空 | 就地提示请输入物品名称  保留图片与其他已填内容 |
| AI 超时或失败 | 不清空图片  显示暂未识别  允许手填并保存 |
| AI 结果迟到 | 用户已编辑名称时不得覆盖  可将结果仅记为内部建议 |
| 重复点击保存 | 按钮进入提交中状态  防止生成重复记录 |
| 图片上传失败 | 保留当前表单  提供重新上传  未成功前不能保存 |
| 拖拽到无效区域 | 卡片回原位  不改变 category_id  不弹错误 |
| 拖错分类 | 分类成功 Toast 提供短时撤销  撤销后恢复原分类或箱子 |
| 删除非空分类 | 先展示受影响物品数  确认后物品回箱  不删除物品 |
| 删除常用位置 | 改为从常用位置中移除  保留已有物品位置快照 |
| 相似或同名物品 | 全部返回  由用户通过图片区分  不强制修改名称 |
| 搜索无结果 | 提示检查名称或确认是否录入  提供添加新物品 |
| 按记录位置未找到 | 保留旧位置  将 location_status 设为 UNCERTAIN |
| 网络或存储异常 | 操作失败时不乐观地移除界面数据  显示可重试提示 |
| 分类或位置名称过长 | 列表换行或截断并可查看全名  不挤压关键操作 |
| 分类同名 | 创建和重命名均阻止完全同名  提示该分类已存在 |

## 16 V1 不做事项

- 真实注册登录  邮箱或手机号验证  忘记密码  退出登录和多用户权限。
- 云端同步  多设备冲突处理和家庭共享衣柜。
- 真实 AI 模型调用  模型训练  模型准确率承诺和自动持续学习。
- 批量上传  多选  批量分类和一键 AI 自动归类。
- AI 语义搜索  自然语言问答  搜索历史和相似推荐。
- 穿搭推荐  购买推荐  社交分享  收藏  使用频率和价值评估。
- 品牌  价格  尺码  材质  颜色标签  备注  购买日期和多张照片。
- 复杂位置层级  地图  RFID  NFC  摄像头或智能衣柜硬件联动。
- 回收站和删除物品后的撤销。
- 主题模式  通知中心  会员体系和未实现的 AI 隐私设置页面。

## 17 开发验收标准

### 17.1 通用完成标准

- 所有 P0 功能可从首页进入并完成  不存在只能通过开发地址访问的孤立页面。
- 刷新页面后已保存的物品  分类和常用位置仍然存在  如采用本地存储需在技术说明中明确。
- 每个状态变更同时更新列表  数量和详情  不出现同一物品在箱子与分类中重复显示。
- 所有危险操作有清晰影响说明  删除物品与删除分类的结果不同。
- PC 和移动端都能完成新增  搜索  查看详情  分类和更新位置。
- 界面不声称已接入真实 AI  不展示虚构准确率  调用量或训练结果。

### 17.3 建议测试用例

- 录入一件有图片  有名称  无位置的物品  确认可保存和搜索。
- 连续录入三件物品  确认箱子顺序与计数。
- 模拟 AI 失败  在未等待模型结果的情况下手填并保存。
- 将箱子物品分类后撤销  再次分类并从详情移回箱子。
- 删除包含多件物品的分类  检查物品未删除且按原 created_at 回箱。
- 搜索两个同名物品  检查图片可区分且两条结果都保留。
- 从常用位置移除一个正在被物品使用的位置  检查历史位置仍显示。
- 在手机宽度下完成查看详情  更新位置和选择分类  不依赖拖拽。
